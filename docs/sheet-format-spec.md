# 曲谱格式规范（Sky Auto Player）

> 本规范由 27 个单元测试验证，全部结论均以实测为准。

## 1. 支持的文件类型

**派发按「内容」而不是「扩展名」决定**（v0.1.5 起）。因为社区分享的曲谱经常是
**`.txt` 后缀但内容是 JSON**，早期版本按扩展名派发，把这类文件送进了纯文本解析器，
解析出 0 个音符，最终表现就是「曲谱没有可播放事件」。

规则：读取字节 → 按 BOM 解码 → 若首字符是 `{` 或 `[` 则用 JSON 解析器，否则用文本解析器；
首选解析器失败会自动回退到另一个。

| 内容 | 使用的解析器 | 说明 |
|---|---|---|
| 以 `{` 或 `[` 开头 | SkyJsonImporter | 不论扩展名是 `.json` 还是 `.txt` |
| 其他 | SkyTextImporter | 简谱 + 老式时间轴 |

**编码**：支持 UTF-8（含 BOM）、**UTF-16 LE/BE（含 BOM）**。
SkyStudio 导出的就是 **UTF-16 LE + BOM**，这点很关键。

## 2. JSON 格式

### 2.1 标准写法（SkyStudio 导出，推荐）

```json
{
  "name": "曲名",
  "bpm": 120,
  "songNotes": [
    { "time": 200, "key": "1Key7" },
    { "time": 400, "key": "1Key5" },
    { "time": 600, "key": "1Key7" },
    { "time": 600, "key": "1Key9" }
  ]
}
```

- `time`：**毫秒**，从曲子开头算起的绝对时间（不是节拍）
- `key`：`1Key0` ~ `1Key14`，尾号就是 0~14 的键位索引
- **同一 `time` 出现多条 = 和弦**（上例 `time:600` 两键同时按下）

### 2.2 你问的那种键值对 —— 可以，但要注意包在哪里

`{"time":200,"key":"1Key7"}` 这个**键值对本身完全正确**。但作为**整个文件**时，
它必须被包在数组里，否则只会被当成一个"文档对象"而找不到音符列表。

**❌ 错误**（整份文件只有这一个对象 → 解析出 0 个音符）
```json
{ "time": 200, "key": "1Key7" }
```

**✅ 正确写法一：顶层数组**
```json
[
  { "time": 200, "key": "1Key7" },
  { "time": 400, "key": "1Key5" }
]
```

**✅ 正确写法二：放进 `songNotes`（推荐）**
```json
{ "name": "曲名", "songNotes": [ { "time": 200, "key": "1Key7" } ] }
```

> 说明：单对象作为整个文件的写法在 v0.1.3 中已兼容，但**仍建议用上面两种**，
> 因为一件作品通常不止一个音。

### 2.3 统一事件流格式（设计文档 §5.5）

```json
{
  "name": "曲名",
  "bpm": 100,
  "events": [
    { "t": 0,   "keys": [0, 2, 4], "hold": 120 },
    { "t": 400, "keys": [5, 7, 9], "hold": 120 },
    { "t": 800, "keys": [10, 12] }
  ]
}
```
- `t`：毫秒；`keys`：键位**数组**（天然支持和弦）；`hold`：按住时长 ms（默认 60）

### 2.4 字段兼容表

| 含义 | 可接受的写法 |
|---|---|
| 音符数组字段 | `songNotes` / `notes` / `events` / `sheets`，或直接顶层数组 |
| 时间 | `time` / `t` / `at` / `timestamp`（毫秒）；`atUs`（微秒） |
| 键位 | `key` / `note` / `k`（单个），`keys`（数组） |
| 按住时长 | `duration` / `hold` / `holdMs`（毫秒）；`holdUs`（微秒） |
| 曲名 | `name` / `songName`；都没有则用文件名 |
| 外层包装 | 直接对象、`[{...}]` 数组、或 `data`/`song`/`sheet`/`payload` 嵌套 |

### 2.5 键位的合法写法

| 写法 | 解析结果 |
|---|---|
| `"1Key7"` | 7 ← **SkyStudio 标准** |
| `"Key7"` | 7 |
| `"2Key7"` | 7（前缀是层号，不参与计算） |
| `"R2C3"` | 7（第 2 行第 3 列） |
| `"A1"` … `"G3"` | 按音名映射 |
| `7`（数字） | 7 |

**超出 0~14 的键会被丢弃，不会自动钳制**（例如 `"1Key99"` 直接忽略，
而不是被塞成 14 凭空多出一个音）。丢弃数量记录在曲谱元数据里。

## 3. TXT 格式

### 3.1 简谱（推荐）

```
// title: 小星星
// bpm: 120
1 2 3 / 4 5 6 // 7 1
-1 -2 -3 0 / 1 2 3
+1 +2
1,3,5 / 2,5
```

| 记号 | 含义 |
|---|---|
| `1`~`7` | 中音区 |
| `-1`~`-7` | 低音区 |
| `+1`~`+7` | 高音区 |
| `0` | 休止（占一拍时间，不出声） |
| `/` | 短停顿 200ms |
| `//` | 长停顿 500ms |
| `//文字` | 段落注释，忽略 |
| `#` | 行注释 |
| `1,3,5` | 和弦（逗号分隔） |
| `// title:` / `// bpm:` | 曲名 / 速度头 |

- 音级 4、7 会**吸附到最近的五声音阶键**（光遇 15 键是三个五声音阶八度）
- 每个音符默认占 `60000 / bpm / 4` 毫秒（120 BPM 时为 125ms）
- 按住时长默认 100ms

### 3.2 老式时间轴（向后兼容）

```
1000 0 70
1300 1+3 70
1600 2 70
```
即 `时间(ms) 键位(+连接) 按住(ms)`。以「时间 ≥ 3 位数字」与简谱区分。

## 4. 常见错误与对应现象

| 现象 | 原因 |
|---|---|
| 提示「曲谱里没有找到任何音符（格式可能不受支持）」 | 解析器认出了文件结构但里面没有音符。v0.1.5 起在**导入时**就报，不再等到点播放 |
| 提示「导入失败：Invalid Sky JSON」 | JSON 语法错误（多余逗号、缺引号等） |
| 导入成功但播放没声音 | **没有做 15 键校准**（详见第 5 节），播放会正常走完但不发任何点击 |
| 找不到文件 | 曲谱没传到手机，或不在文件选择器打开的那个目录 |

### 4.1 实战案例：`龙卷风.txt`

用户提供的真实曲谱，已收录为回归测试（`RealUserSheetTest`）：

| 项 | 值 |
|---|---|
| 文件名 | `龙卷风.txt` |
| 实际内容 | **UTF-16 LE + BOM 的 JSON** |
| 顶层结构 | `[ { ... } ]`（数组包一个对象） |
| 音符数 | 232 |
| 键位 | `1Key4` ~ `1Key14` |
| 时长 | 92 秒（0 ~ 92000 ms） |
| BPM | 240 |
| 附加字段 | `arrangedBy` `transcribedBy` `permission` `isComposed` `bitsPerPage` `isEncrypted` |

这类文件在 v0.1.4 及以前**无法导入**（按扩展名派发 → 送进纯文本解析器 → 0 音符）。
v0.1.5 起按内容嗅探，直接可用。

---

## 5. 重要提醒：必须先校准

代码中未找到校准档时的行为是**返回空坐标集、不发送任何手势**。
也就是说未校准时播放进度条会正常走完、状态显示"播放中"，但游戏里**一个音都不响**。
换手机后同样需要重新校准。
